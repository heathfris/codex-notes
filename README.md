# Codex 使用记录

记录个人使用 Codex 时遇到的问题、排查证据和可复用的解决方法。

## Windows 本地 HTML 预览：中文路径导致“在外部浏览器中打开”失败

- 记录日期：2026-10-30。
- 受影响版本：Windows 安装包 `OpenAI.Codex_26.1027.3384.0_x64__2p2nqsd0c76g0`。
- 系统：Windows 11 家庭版中文版，`10.0.26200`，x64。
- 官方反馈：[openai/codex #58284](https://github.com/openai/codex/issues/58284)。
- 当前采用的方法：通过本机 HTTP 提供网页预览，继续使用原来的“在外部浏览器中打开”按钮。

### 问题从哪里出现

日常工作中，Codex 生成本地 HTML 网页后，可以在内置浏览器中正常预览。但当文件所在路径包含中文时，点击“在外部浏览器中打开”，页面无法在系统浏览器中打开。

不同网页使用的目录和文件名不同，因此从使用体验上看，按钮像是时好时坏。已做的地址对照把问题缩小到了中文本地文件 URL 的外部打开环节。

这份记录中的路径均为示例，不是实际工作文件的位置。

### 已确认的对照结果

| 预览地址 | 内置浏览器 | “在外部浏览器中打开” |
| --- | --- | --- |
| 中文路径的本地 `file://` 地址 | 可以正常预览 | 打开失败 |
| 英文路径的本地 `file://` 地址 | 正常 | 打开成功 |
| 中文路径的 HTTP 地址 | 正常 | 打开成功 |
| 英文路径的 HTTP 地址 | 正常 | 打开成功 |

这里的英文路径对照指整个文件路径不含中文。仅把 HTML 文件名改成英文，不能排除上级目录中的中文。

### Windows 原生调用的排查证据

直接调用 Windows `ShellExecuteExW` 时，已有的中文路径文件得到以下对照结果：

| 传入形式 | 结果 |
| --- | --- |
| 经过百分号编码的中文文件 URL | 返回错误 `2`，即 `ERROR_FILE_NOT_FOUND` |
| 保留原始中文字符的文件 URL | 打开成功 |
| 包含原始中文字符的 Windows 原生文件路径 | 打开成功 |

三种形式可以用下面的示例说明：

```text
file:///C:/codex-preview/%E4%B8%AD%E6%96%87/%E9%A2%84%E8%A7%88.html
file:///C:/codex-preview/中文/预览.html
C:\codex-preview\中文\预览.html
```

错误 `2` 来自直接调用原生 API 的对照测试。它不是从 Codex 按钮中截获的报错，也还没有截获 Codex 实际传给 Windows 的启动参数、标志和调用链。

### 原因判断

这些对照说明，中文路径中的文件可以读取，HTML 可以渲染，系统也能打开原生中文路径和普通 HTTP 地址。

因此，优先排查方向是：编码后的本地文件 URL 在交给 Windows 外部打开入口时，没有经过适当的 URL 与原生路径转换。具体是 Codex 的哪段实现负责这一过程，目前尚未确认。

这份记录区分了实际观察到的现象和基于对照结果提出的原因推断。

### 最省事的使用方法

提供网页预览时，由 Agent 自动启动或复用本机 HTTP 服务，再在内置浏览器打开对应 HTTP 地址。用户继续点击原来的“在外部浏览器中打开”按钮。

这样可以避开此次排查中失败的中文 `file://` 打开流程，文件和目录仍然可以使用中文。日常使用时，启动服务和生成正确地址由 Agent 完成。

需要手动操作时，可在 PowerShell 中运行下面的示例命令，把目录替换成自己的项目目录：

```powershell
py -m http.server 8765 --bind 127.0.0.1 --directory "C:\codex-preview"
```

在内置浏览器打开 [本机预览目录](http://127.0.0.1:8765/)，进入对应 HTML，再点击外部打开按钮。用完后在运行服务的终端按 `Ctrl+C` 停止；如果端口已被占用，应复用适合当前项目的服务或选择其他端口。

### 可以加入 AGENTS.md 的规则

下面这条规则已作为本次工作流的处理方式：

```text
提供本地 HTML 网页预览时，自动启动或复用本机 HTTP 服务，
并在内置浏览器打开对应 HTTP 地址，确保用户能继续使用
“在外部浏览器中打开”按钮。避免使用 file:// 作为网页预览入口。
```

这是预览工作流的绕过方法。Codex 按钮对中文本地文件 URL 的处理仍需产品端修复。

### 产品端建议

建议检查 Windows 外部打开入口：对 `file:` URL 按文件 URL 规则解析，并在需要原生路径的调用边界完成一次正确的 Unicode 转换；HTTP 和 HTTPS 保持已有流程。

转换需要覆盖中文、空格、文件名中的 `%` 和 `#`、UNC 路径，并保留查询参数和页面片段应有的浏览器语义。直接换成通用文件打开接口，还应确认它不会因 `.html` 的文件关联而打开编辑器。

外部启动失败时，界面也应显示可诊断的错误信息。
